# Apple Watch 与 iPhone 快捷指令

MuseLab 通过一条「MuseLab」快捷指令提供 Apple Watch 接入。可以语音发送消息、浏览最近会话与回复，并在同一会话继续对话。iPhone 也可以运行同一条指令。

## 安装与配置

1. 将自己的 MuseLab 升级到 **v2.1.0 或更新版本**，准备一个手机和手表能访问的 HTTPS 地址，以及该实例的 MuseLab token。
2. 在 iPhone 用 Safari 打开 [MuseLab v2.1.0 发布页](https://github.com/hesorchen/muselab/releases/tag/v2.1.0)，下载已签名的 `MuseLab-v5.shortcut`，打开并添加快捷指令。
3. 根据导入问题填写服务器地址和 token。地址示例为 `https://muselab.example`，末尾不要加 `/`。如果没有出现导入问题，在编辑器顶部的「服务器地址」「MuseLab token」两个文本操作中填写。客户端编号保持原值。
4. 先在 iPhone 运行一次，允许连接自己的服务，确认出现菜单。
5. 在快捷指令详细信息中开启「在 Apple Watch 上显示」，待 iCloud 同步后，在手表的「快捷指令」App 中运行。

发布模板只包含占位符。下载和签名时不需要提供真实服务器 token；仅在导入到自己的设备后填写。

## 主菜单与连续对话

| 功能 | 行为 |
| --- | --- |
| ➕ 新建并发送 | 主菜单第一项。输入并确认后创建会话并发送；取消或空输入不会创建空会话 |
| 🎙️ 继续上次会话 | 向这条指令上次使用的会话发送消息；没有记录时显示最近会话 |
| 🗂️ 最近会话 | 当前默认工作区最近更新的 10 个会话，无搜索和列表分页 |
| 📖 查看最近回复 | 查看上次会话最近的文字回复、时间和当前状态 |

选择会话后，可以发送消息、查看最近回复或最近 6 条文字对话、查看排队消息，以及停止当前执行。

在手表输入界面使用系统麦克风进行语音输入。确认发送后仅提示「消息发送成功，Muse 正在处理中」，随后回到当前会话。看完回复后选择「继续对话」即可发送下一条；「刷新回复」重新读取最近已有的文字输出。长内容按段显示，可选择「继续阅读」。

成功提示表示请求已经接受并排队，不能代替完成状态；最近回复也可能来自上一轮。需要工具授权时，在 MuseLab 网页处理。

排队消息撤回和停止执行均需确认。停止操作绑定当前轮次，停止后保留队列。每级菜单可返回或退出；取消系统输入、选择或确认会结束本次指令。一次运行最多处理 40 次菜单交互，之后重新打开即可。

iPhone 和 Watch 共用客户端编号及最近会话记录。服务端在私有状态目录保存记录，重启后仍可继续使用。若希望多份指令分别记住最近会话，可在顶部使用不同的 UUID。

## 排查

- **没有出现菜单或提示返回内容无法读取**：检查 HTTPS 地址、token 和网络权限。地址应为 MuseLab 服务根地址，不能填写发布页或下载链接。模板会先提取请求结果的文本、解析为字典，再读取界面字段；网页或非菜单格式的返回会显示连接提示。
- **菜单已失效**：返回主菜单重新选择。动作有有效期，并绑定客户端和工作区。
- **发送后回复没变化**：请求可能尚在队列或执行中。查看会话状态并手动刷新；该入口不进行后台自动轮询。
- **Watch 找不到指令**：检查「在 Apple Watch 上显示」、配对账户的 iCloud 快捷指令同步，先在 iPhone 成功运行再尝试手表。
- **修改模板后无法导入**：重新生成并签名。发布文件已签名，不需要用户在 Mac 上签名。

菜单和输入界面使用系统快捷指令组件；自定义聊天布局和动效需另行开发原生 watchOS App。自动测试涵盖协议、队列与模板数据流，实际设备的导入、权限、语音输入和同步应在安装时确认。

## 开发与版本

生成不含凭证的源模板：

```bash
python3 scripts/build_watch_console.py --output /tmp/muselab-watch
```

输出 `MuseLab.unsigned.shortcut` 和 `MuseLab.xml.plist`。修改后需重新签名才能分发。v5 的发布文件由 RoutineHub HubSign 对占位符模板签名，发布前检查了签名、证书链、变量引用与源模板一致性。

源码与测试随 MuseLab 维护；签名文件作为 Release 附件分发。快捷指令模板版本（v5）和菜单协议版本（v2）分别管理。

`GET /api/watch/menu?client_id=<UUID>` 获取主菜单；`POST /api/watch/actions` 处理菜单动作。均要求 `X-Auth-Token`，响应使用 `Cache-Control: no-store`。界面类型为 `menu`、`input`、`confirm`、`message`、`exit`。动作经签名且限时，绑定客户端和工作区；输入需确认后提交。

基础适配接口包括最近会话、消息提交、提交回执和最近回复。消息沿用 MuseLab 的持久队列与 `request_id` 去重；掉线不会取消服务端已经接受的提交。接口验证和源码位置见 `backend/api_watch.py`、`backend/api_watch_console.py`、`tests/test_api_watch.py`、`tests/test_watch_console.py` 与 `tests/test_watch_shortcut.py`。
